# 동네공부방

서울사이버대 UI/UX 프로그래밍 실습 프로젝트.
걸어서 갈 수 있는 동네 공부방을 시간 단위로 예약하는 서비스다.

- 배포 주소: https://monkeymagic92.github.io/uiuxprogramming/
- 저장소: https://github.com/monkeymagic92/uiuxprogramming

## 서비스 개요

| 항목 | 내용 |
|---|---|
| 사용자 | 이번 주 안에 집 근처에서 조용히 공부할 자리를 잡고 싶은 사람 |
| 서비스 목적 | 독서실처럼 한 달을 등록하지 않고, 동네 공부방을 필요한 시간만큼만 빌려 쓴다 |
| 핵심 행동 | 동네·자리·날짜·시간을 골라 공부방 예약을 확정한다 |
| 완료 조건 | 확인 화면에서 고른 내용을 검토하고 "예약이 확정되었습니다" 화면에 도달한다 |

페이지는 서비스 소개 → 주요 기능(탭) → 이용 방법 → 예약 준비 → 공부방 예약 → 소식 받기 순서다.
이용 방법에 적어둔 3단계(동네 선택 → 날짜·시간 선택 → 예약 확정)를 7주차에 실제로 눌러볼 수 있는 흐름으로 만들었다.

## 사용자 흐름

```
예약 준비: 이름 입력 + 이용 규칙 확인 → [예약 시작하기]
  1 / 3 공부방 선택   : 동네(필수), 자리 종류        → [날짜·시간 고르기]
  2 / 3 날짜·시간 선택 : 이용 날짜(필수), 시작 시간(필수), 이용 시간
                         [공부방 다시 고르기] ←       → [예약 내용 확인하기]
  3 / 3 내용 확인      : 예약자 / 공부방 / 날짜·시간
                         [날짜·시간 수정하기] ←       → [예약 확정하기]
  예약 완료            : 확정 문장 + 취소 안내      → [다시 예약하기] → 1 / 3
```

- 6주차에 만든 "예약 시작하기" 버튼(규칙을 확인해야 활성화)을 흐름의 입구로 썼다.
  규칙 확인 조건은 그대로 두고, 이름이 비어 있는지만 추가로 확인한다.
- 예약자 이름은 6주차 예약 준비 영역의 이름 칸을 그대로 쓴다. 흐름 안에서 한 번 더 묻지 않는다.
- 단계는 진행 표시(1 / 3 · 공부방 선택)로 지금 어디인지 보여 주고, 완료되면 "예약 완료"로 바뀐다.
- 단계가 바뀌면 새 단계의 첫 입력칸이나 버튼으로 포커스를 옮긴다.
  처음엔 이걸 안 해서 숨겨진 단계의 버튼에 포커스가 남아 있었다.

## 인터랙션 시나리오

| 행동 | 이벤트 · 조건 | 화면 반응 → 다음 상태 |
|---|---|---|
| 규칙 확인 후 이름 없이 예약 시작 | click · 이름이 비어 있음 | 이름 칸 아래에 "예약자 이름을 입력해 주세요" 안내, 이름 칸 붉게 표시하고 포커스 → 예약 영역은 열리지 않음 |
| 이름 쓰고 예약 시작 | click · 이름 있음 | 안내 지움, 공부방 예약 영역이 열림 → 1 / 3 공부방 선택 |
| 동네 없이 다음 | click · 동네 빈 값 | 동네 칸 붉게, "동네를 선택해 주세요" 안내 → 1단계에 머묾 |
| 자리 종류를 스터디룸으로 바꿈 | change · 스터디룸 | 같이 오는 사람도 규칙을 지켜야 한다는 안내 표시. 1인석으로 바꾸면 숨김 |
| 날짜나 시작 시간 없이 다음 | click · 날짜 또는 시간 빈 값 | 빠진 칸만 붉게, 날짜가 먼저 빠졌으면 날짜 안내 → 2단계에 머묾 |
| 확인 단계에서 날짜·시간 수정하기 | click · 수정 요청 | 입력값을 지우지 않고 2단계로 → 고친 뒤 다시 확인하면 새 값으로 다시 채움 |
| 예약 확정하기 | click | 진행 표시가 "예약 완료"(초록)로 바뀌고 확정 문장 표시 → 완료 |
| 다시 예약하기 | click · 초기화 | 동네·자리·날짜·시간·이용 시간, 오류 문구와 붉은 표시, 스터디룸 안내, 확인·완료 문장, 진행 표시를 처음으로 → 1 / 3 |

다시 예약하기에서 이름과 규칙 확인은 지우지 않는다. 둘은 예약 흐름이 아니라 그 앞의 예약 준비 영역 값이고,
같은 사람이 한 번 더 예약하는 경우라 다시 쓰게 할 이유가 없다고 봤다.

확인 화면 값은 "예약 내용 확인하기"를 누를 때마다 지금 입력칸 값으로 다시 채운다.
그래서 이전 단계에서 고친 값이 따로 처리하지 않아도 확인 화면에 반영된다.

## 주차별 작업 기록

### 2주차 - HTML 구조

1주차엔 h1이랑 p 두 줄이 전부였는데, 이번에 header / main / footer로 나눴다.
main 안에는 서비스 소개, 주요 기능, 이용 방법, 소식 받기를 각각 section으로 묶고 id를 달았다.

이렇게 한 이유는:

- 처음 온 사람이 "뭐 하는 서비스지 → 뭘 할 수 있지 → 어떻게 쓰지" 순서로 읽게 하고 싶었다.
  이 순서를 body 첫 줄 주석에 먼저 적어두고 그대로 section 순서로 옮겼다.
- 주요 기능은 순서를 바꿔도 상관없어서 ul, 이용 방법은 순서를 지켜야 해서 ol로 했다.
- nav의 href랑 section의 id를 맞춰서 원하는 영역으로 바로 넘어가게 했다.
- alt는 파일명 말고 그 자리에서 이미지가 무슨 얘기를 하는지 적었다.
- label의 for랑 input의 id를 email로 맞춰서 라벨을 눌러도 입력칸이 잡히게 했다.

### 2주차 - 구조 비교 메모

같은 화면을 시맨틱 태그 없이 div로만 짜면 이렇게 된다.

```html
<div class="top">
  <div class="title">동네공부방</div>
  <div class="menu"><a href="#about">서비스 소개</a></div>
</div>
```

브라우저에 보이는 결과는 거의 같은데, 차이는 세 군데였다.

**정보 계층** - div는 전부 같은 무게라서 코드만 봐서는 뭐가 제목이고 뭐가 본문인지 알 수 없다.
h1 → h2 → h3을 쓰면 읽는 순서가 코드에 그대로 남는다. 목록도 ul이냐 ol이냐에 따라
"순서가 있는 과정"인지 "순서 상관없는 항목"인지까지 표시된다.

**시맨틱 구조** - header, nav, main, section, footer는 태그 이름 자체가 그 덩어리의 역할이다.
div.top, div.menu 같은 건 클래스 이름을 지은 사람만 안다. 나중에 코드를 다시 볼 때도 차이가 크다.

**접근성** - 스크린리더는 시맨틱 태그를 기준으로 영역을 건너뛴다. div만 있으면 그게 안 돼서
처음부터 끝까지 순서대로 들어야 한다. label-input 연결이나 alt도 같은 이야기다.
없으면 이 입력칸이 뭘 넣는 칸인지, 이미지가 무슨 그림인지 알 방법이 없다.

### 3주차 - CSS

.feature-list에 display: flex랑 gap: 20px을 주고, .feature-card에 flex: 1과 배경색, 테두리를 넣었다.

세로로 길게 늘어지던 기능 3개가 같은 너비 카드로 한 줄에 들어갔고 간격도 일정해졌다.
세 기능이 같은 종류의 정보라는 게 한눈에 보여서 비교하면서 읽기 편해졌다.

### 4주차 - 반응형

#### 확인한 문제

개발자 도구를 390px로 놓고 3주차 화면을 열어봤다.

- 메뉴 4개가 한 줄에 그대로 남아서 글자가 서로 붙었다.
- 소개 글과 이미지가 가로로 붙어 있어 글이 한 줄에 서너 글자씩만 들어갔다.
- 기능 카드 3개가 flex: 1로 균등 분할되면서 카드 하나 폭이 100px도 안 됐다.
- 이메일 입력창과 버튼이 서로 밀어내서 버튼 글자가 두 줄로 깨졌다.

#### 수정한 내용

viewport 메타 태그는 1주차에 이미 넣어둬서 그대로 뒀다.

- header / main / footer에 width: 100%를 추가했다. max-width: 1100px만 있으면
  넓은 화면은 잡히지만 좁은 화면에서 안쪽 여백까지 계산이 안 맞았다.
- .service-image를 width: 360px에서 width: 100% + max-width: 360px + height: auto로 바꿨다.
  화면이 좁아지면 이미지가 따라 줄고, 넓어져도 360px을 넘지 않는다.
- .site-nav와 .about-layout에 flex-wrap: wrap을 줘서 자리가 부족하면 다음 줄로 넘어가게 했다.
- .feature-list를 flex에서 grid로 바꿨다.
  grid-template-columns: repeat(auto-fit, minmax(260px, 1fr))이라서
  들어갈 수 있는 만큼만 열을 만들고 카드는 최소 260px을 지킨다.
  flex: 1일 때처럼 무조건 3등분되지 않는다. .feature-card의 flex: 1은 지우고 min-width: 0을 넣었다.
- 파일 맨 아래에 @media (max-width: 768px) 블록을 하나 추가해서
  메뉴 / 소개 / 기능 카드 / 폼을 전부 한 열로 바꾸고 글자 크기와 여백을 줄였다.

#### 달라진 점

1100px / 769px / 768px / 390px에서 확인했다.

| 너비 | 결과 |
|---|---|
| 1100px | 카드 3열, 소개 글과 이미지 가로 배치 |
| 769px | 카드 2열. 미디어 쿼리는 아직 안 걸린다 |
| 768px | 메뉴·카드·폼이 한 열로 바뀐다 |
| 390px | 가로 스크롤 없음, 버튼이 화면 폭에 꽉 참 |

한 군데 걸린 게 있다. 768px 이하에서 .about-layout이 세로 배치가 되니까
이미지에 준 flex: 0 1 360px의 360px이 너비가 아니라 높이 기준으로 잡혀서
이미지가 세로로 늘어났다. 미디어 쿼리 안에서 flex: 0 1 auto로 되돌려서 해결했다.
flex-basis가 방향에 따라 다른 축을 가리킨다는 걸 이번에 알았다.

### 5주차 - JavaScript로 신청 결과 알려주기

#### 추가한 기능

소식 받기 영역의 빈자리 알림 신청 폼에 JavaScript를 붙였다.
4주차까지는 버튼을 눌러도 페이지가 새로고침될 뿐 신청이 됐는지 알 방법이 없었다.

- body 닫는 태그 바로 위에서 script.js를 불러오고, Console에 연결 문장이 찍히는지 먼저 확인했다.
- 폼, 이메일 입력칸, 안내 문구(#subscribeMessage), 버튼(#subscribeButton)을 querySelector로 선택했다.
- 폼의 submit 이벤트에 subscribe 함수를 연결했다.
  버튼 click 대신 submit을 쓴 건 입력칸에서 엔터를 쳐도 똑같이 동작하게 하려고.
  submit은 기본으로 페이지를 새로고침해서 event.preventDefault()로 막았다.

#### 조건 처리

| 입력 | 안내 문구 | 스타일 / 버튼 |
|---|---|---|
| 비어 있음 | 이메일을 입력해 주세요. | 붉은 배경(is-error), 입력칸에 다시 포커스 |
| 이메일 입력 | ○○ 으로 빈자리 알림을 보내 드릴게요. | 초록 배경(is-done), 버튼 "신청 완료" + disabled |

문구는 makeSubscribeMessage 함수가 입력값을 받아 if로 골라서 돌려준다.
신청 여부는 let isSubscribed에 담았다. false로 시작해서 신청하면 true가 된다.
신청이 끝나면 버튼과 입력칸을 disabled로 막아서 같은 신청이 반복되지 않게 했다.

@가 빠진 값은 input type="email"이 제출 자체를 막아서 브라우저 기본 안내가 뜬다.
그래서 JavaScript 쪽 조건은 빈 값인지 아닌지만 나눴다.

#### 확인

- 빈 값 제출 → 경고 문구, 버튼 그대로
- 이메일 입력 후 제출 → 완료 문구, 버튼 비활성화, 새로고침 없음
- 390px 폭에서 버튼과 문구가 잘리지 않고 가로 스크롤 없음
- Console 오류 없음

### 6주차 - 이벤트와 탭

#### 추가한 기능

이용 방법 다음에 "예약 준비" 섹션(#prepare)을 새로 만들고 메뉴에도 링크를 달았다.
기존 주요 기능 카드 3개는 탭으로 바꿨다.

| 이벤트 | 요소 | 화면 변화 |
|---|---|---|
| click | 화면 밝기 버튼(#themeButton) | body에 dark 클래스를 붙였다 뗐다 하면서 배경·카드 색이 바뀌고, 버튼 문구가 "어두운 화면으로 보기" ↔ "밝은 화면으로 보기"로 바뀐다 |
| input | 예약자 이름(#userName) | 쓰거나 지울 때마다 "0 / 10" 글자 수가 바뀐다. 10자를 채우면 is-full 클래스로 숫자가 붉게 굵어진다 |
| change | 이용 규칙 체크박스(#agreeCheck) | 안내 문구가 바뀌고, is-ready 클래스로 초록 배경이 되고, 예약 시작하기 버튼의 disabled가 풀린다. 체크를 해제하면 셋 다 원래대로 |
| click | 주요 기능 탭 3개(.tab) | 누른 탭만 초록색으로 채워지고, data-target으로 연결된 패널 하나만 보인다 |

change 쪽은 checked 값 하나(agreed)로 문구, 클래스, 버튼 상태를 같이 바꿨다.
기준이 하나라서 체크를 켜고 끌 때 셋이 항상 같은 상태로 움직인다.

예약 시작하기 버튼은 지금은 활성/비활성만 바뀌고 누른 뒤 동작은 없다.
예약 흐름은 다음 주차에 붙일 생각이다.

#### 탭으로 바꾼 이유

빈자리 확인 / 시간 단위 예약 / 이용 후기는 원래 카드 세 장이 나란히 있었는데,
한 줄 설명만 있어서 기능마다 설명을 더 쓰기엔 카드가 좁았다.
탭으로 바꾸면서 기능마다 설명을 한 문단씩 더 넣었고, 한 번에 하나만 보이니 화면도 덜 길어졌다.

- 탭은 querySelectorAll로 전부 잡고 forEach로 click을 연결했다.
- 누르면 resetTabsAndPanels로 전부 끄고 activateTab으로 누른 것만 켠다.
  is-active 클래스, aria-selected, 패널의 hidden을 같이 바꾼다.
- 탭 버튼의 data-target="#panel-booking"과 패널 id="panel-booking"을 맞춰서 연결했다.
- 기능 카드에 쓰던 .feature-list / .feature-card CSS는 안 쓰게 돼서 지웠다.

#### 테스트 결과

1100px / 768px / 390px 폭에서 확인했다.

| 확인 항목 | 결과 |
|---|---|
| 탭 세 개를 차례로 누르기 | 선택된 탭과 보이는 패널이 항상 하나씩 |
| 화면 밝기 버튼 두 번 누르기 | 어두운 화면 → 밝은 화면, 버튼 문구도 따라 바뀜 |
| 이름 입력 / 지우기 | 2 / 10 → 10 / 10(붉게) → 0 / 10 |
| 체크 → 해제 | 버튼 활성 → 비활성, 문구·배경도 같이 돌아옴 |
| 1100px | 탭 가로 한 줄, 버튼은 글자 폭만큼 |
| 768px | 탭이 세로로 쌓이고 버튼이 카드 폭에 꽉 참 |
| 390px | 가로 스크롤 없음, 탭·입력창·버튼 잘림 없음 |
| 키보드 | Tab으로 탭 사이 이동, Enter/Space로 탭 전환, Space로 체크박스 선택 |
| Console | 연결 확인 문장 외 오류 없음 |

어두운 화면을 만들 때 body.dark p로 문단 글자를 밝게 바꿨는데,
안내 문구(#agreeMessage)는 배경이 밝은 상자라 그대로 두면 밝은 글자가 밝은 배경 위에 올라간다.
그래서 #agreeMessage에는 글자색을 직접 지정해서 id 선택자가 body.dark p보다 우선하게 했다.
