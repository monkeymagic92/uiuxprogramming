# 동네공부방

서울사이버대 UI/UX 프로그래밍 실습 프로젝트.
집 근처 공부방을 시간 단위로 예약하는 서비스의 소개 페이지다.

## 2주차 - HTML 구조

1주차엔 h1이랑 p 두 줄이 전부였는데, 이번에 header / main / footer로 나눴다.
main 안에는 서비스 소개, 주요 기능, 이용 방법, 소식 받기를 각각 section으로 묶고 id를 달았다.

이렇게 한 이유는:

- 처음 온 사람이 "뭐 하는 서비스지 → 뭘 할 수 있지 → 어떻게 쓰지" 순서로 읽게 하고 싶었다.
  이 순서를 body 첫 줄 주석에 먼저 적어두고 그대로 section 순서로 옮겼다.
- 주요 기능은 순서를 바꿔도 상관없어서 ul, 이용 방법은 순서를 지켜야 해서 ol로 했다.
- nav의 href랑 section의 id를 맞춰서 원하는 영역으로 바로 넘어가게 했다.
- alt는 파일명 말고 그 자리에서 이미지가 무슨 얘기를 하는지 적었다.
- label의 for랑 input의 id를 email로 맞춰서 라벨을 눌러도 입력칸이 잡히게 했다.

## 2주차 - 구조 비교 메모

같은 화면을 시맨틱 태그 없이 div로만 짜면 이렇게 된다.

```html
<div class="top">
  <div class="title">동네공부방</div>
  <div class="menu"><a href="#about">서비스 소개</a></div>
</div>
```

브라우저에 보이는 결과는 거의 같은데, 차이는 세 군데였다.

**정보 계층** - div는 전부 같은 무게라서 코드만 봐서는 뭐가 제목이고 뭐가 본문인지 알 수 없다.
h1 → h2 → h3을 쓰면 읽는 순서가 코드에 그대로 남는다. 목록도 ul이냐 ol이냐에 따라
"순서가 있는 과정"인지 "순서 상관없는 항목"인지까지 표시된다.

**시맨틱 구조** - header, nav, main, section, footer는 태그 이름 자체가 그 덩어리의 역할이다.
div.top, div.menu 같은 건 클래스 이름을 지은 사람만 안다. 나중에 코드를 다시 볼 때도 차이가 크다.

**접근성** - 스크린리더는 시맨틱 태그를 기준으로 영역을 건너뛴다. div만 있으면 그게 안 돼서
처음부터 끝까지 순서대로 들어야 한다. label-input 연결이나 alt도 같은 이야기다.
없으면 이 입력칸이 뭘 넣는 칸인지, 이미지가 무슨 그림인지 알 방법이 없다.

## 3주차 - CSS

.feature-list에 display: flex랑 gap: 20px을 주고, .feature-card에 flex: 1과 배경색, 테두리를 넣었다.

세로로 길게 늘어지던 기능 3개가 같은 너비 카드로 한 줄에 들어갔고 간격도 일정해졌다.
세 기능이 같은 종류의 정보라는 게 한눈에 보여서 비교하면서 읽기 편해졌다.
