# 동네공부방

서울사이버대 UI/UX 프로그래밍 실습 프로젝트.
걸어서 갈 수 있는 동네 공부방을 시간 단위로 예약하는 서비스다.

- 배포: https://monkeymagic92.github.io/uiuxprogramming/
- 저장소: https://github.com/monkeymagic92/uiuxprogramming

## 서비스 개요

| 항목 | 내용 |
|---|---|
| 사용자 | 이번 주 안에 집 근처에서 조용히 공부할 자리를 잡고 싶은 사람 |
| 서비스 목적 | 독서실처럼 한 달을 등록하지 않고, 동네 공부방을 필요한 시간만큼만 빌려 쓴다 |
| 핵심 행동 | 동네·자리·날짜·시간을 골라 공부방 예약을 확정한다 |
| 완료 조건 | 확인 화면에서 고른 내용을 검토하고 "예약이 확정되었습니다" 화면에 도달한다 |

페이지는 서비스 소개 → 주요 기능(탭) → 이용 방법 → 자주 묻는 질문(12주차) → 예약 준비 → 공부방 예약 → 내 예약 → 이용 후기 쓰기 → 소식 받기 순서다.
이용 방법에 적어둔 3단계(동네 선택 → 날짜·시간 선택 → 예약 확정)를 7주차에 실제로 눌러볼 수 있는 흐름으로 만들었다.
상단 메뉴(10주차)는 서비스 소개 / 예약하기 / 내 예약 / 후기 쓰기 / 빈자리 알림 다섯 개다.

## 중간고사 추가 기능: 내 예약

7주차는 예약 확정 화면에서 끝났고, 확정한 예약을 다시 볼 방법이 없었다.
그래서 확정한 예약이 쌓이는 "내 예약" 목록을 만들고, 거기서 예약을 다시 열어 보거나 취소할 수 있게 했다.
확정할 때 이미 있는 예약과 시간이 겹치는지도 확인한다.

연결 지점은 7주차 흐름의 끝이다. "예약 확정하기"를 누르면 목록에 추가되고, 완료 화면에 "내 예약 보기" 버튼이 생겼다.

공부방 이용자는 예약하고 나서 "언제 어디로 가기로 했지?"를 다시 확인하고, 일정이 바뀌면 취소해야 한다.
같은 사람이 같은 시간에 두 곳을 잡는 것도 막아야 해서 겹침 검사를 같이 넣었다.

### 행동 → 조건 → 반응 → 다음 행동

| 사용자 행동 | 확인할 조건 | 성공 반응 | 다른 분기의 반응 | 다음 행동 |
|---|---|---|---|---|
| 확인 화면에서 예약 확정하기 | 같은 날짜에 취소하지 않은 예약과 시간이 한 시간이라도 겹치는가 | 안 겹치면 목록 맨 위에 추가하고 예약 완료 화면으로 넘어감 | 겹치면 확정하지 않는다. 확인 화면에 "○○부터 ○시간 동안 ○○ 예약이 이미 있습니다" 안내, 날짜·시간을 붉게 표시하고 "날짜·시간 수정하기"로 포커스 | 수정하기 → 2단계(값 유지) → 시간 바꿔서 다시 확인 |
| 완료 화면에서 내 예약 보기 | | 내 예약 목록의 방금 넣은 예약(맨 위)으로 포커스 이동 | | 자세히 보기 / 예약 취소 |
| 내 예약 열기 | 확정한 예약이 있는가 | 예약마다 공부방·자리, 날짜·시간, 상태(예약됨) 표시 | 하나도 없으면 "아직 확정한 예약이 없습니다" 안내 | 새로 예약하기 |
| 자세히 보기 | | 예약자, 이용 시간(13:00 ~ 15:00), 취소 가능 시각 펼침. 버튼이 "접기"로 바뀜 | 접기를 누르면 다시 숨김 | 예약 취소 / 접기 |
| 예약 취소 | 지금이 이용 시작 1시간 전보다 이른가 | 상태가 "취소됨"으로 바뀌고, 카드가 점선·흐린 배경, 시간에 취소선, 버튼은 "취소 완료"로 비활성화. 목록 위에 취소 안내(초록) | 기한이 지났으면 취소하지 않는다. "취소 기한(이용 1시간 전)이 지나 취소할 수 없습니다" 안내(붉게), 상태 그대로 | 취소하면 그 카드의 자세히 보기로 포커스(11주차에 바꿈, 예약됨 필터에서는 카드가 빠지므로 선택된 필터 버튼). 취소한 시간은 겹침 검사에서 빠져서 같은 시간에 다시 예약할 수 있다 |
| 새로 예약하기 | 예약 흐름을 연 적이 있는가 | 열려 있으면 다시 예약하기와 같은 초기화 후 1단계 | 아직이면 예약 준비의 이름 칸으로 이동 | 공부방 선택 / 이름·규칙 확인 |

- 목록은 배열(myBookings)에 예약을 객체로 담고, 바뀔 때마다 renderMyBookings로 다시 그린다.
  목록 한 줄의 HTML은 index.html의 template에 두고 script.js는 복사해서 값만 채운다. 구조는 HTML 쪽에 남기고 싶었다.
- 취소는 목록 전체를 다시 그리지 않고 그 카드의 상태만 바꾼다(showBookingStatus). 펼쳐 둔 자세히 보기가 접히지 않게 하려고.
- 겹침 판단은 "새 시작 < 기존 끝 그리고 기존 시작 < 새 끝"이다. 13:00~15:00 예약이 있으면 11:00부터 3시간은 겹치고, 15:00부터는 안 겹친다.
- 10주차에 필터가 생기면서, "예약됨"만 보고 있을 때 취소하면 그 카드가 빠져야 해서 그때만 목록을 다시 그린다.
- 중간고사 때는 새로고침하면 목록이 비워졌다. 10주차에 필터로 다시 볼 수 있게 localStorage(dongneBookings)에 저장하도록 바꿨다.

## 10주차 추가 기능: 메뉴와 내 예약 필터

메뉴가 7개로 늘어나 있었고, 눌러도 지금 어디를 보고 있는지 표시가 없었다. 모바일에서는 7개가 세로로 길게 깔려 본문이 한참 아래로 밀렸다.
그리고 내 예약이 쌓이면 취소한 예약과 아직 유효한 예약이 섞여서 "갈 곳"만 골라 보기 어려웠다.

### 메뉴별 목적지

메뉴는 nav > ul > li 구조다. 순서는 알아보기 → 예약하기 → 결과 확인 → 후기·알림.

| 메뉴 | 목적지 | 도착하는 곳 |
|---|---|---|
| 서비스 소개 | `#about` | 서비스 소개. 바로 아래에 주요 기능, 이용 방법이 이어진다 |
| 예약하기 | `#prepare` | 예약 준비(이름·규칙 확인 → 예약 시작하기). 예약 흐름은 이 아래에 열린다 |
| 내 예약 | `#myBookings` | 확정한 예약 목록과 필터 |
| 후기 쓰기 | `#writeReview` | 이용 후기 쓰기 폼과 최근 후기 |
| 빈자리 알림 | `#subscribe` | 이메일 빈자리 알림 신청 |

- 주요 기능·이용 방법은 서비스 소개 바로 아래라 따로 메뉴를 두지 않았다. "예약 준비"는 무엇을 하는 곳인지 바로 안 읽혀서 메뉴 이름을 "예약하기"로 했다.
- 현재 위치는 주소의 # 값으로 정한다(updateCurrentNav). 맞는 메뉴 하나에만 is-current와 aria-current="page"를 붙이고 나머지에서는 뗀다.
  #가 없으면 맨 위를 보고 있는 것이라 첫 메뉴(서비스 소개)를 표시한다.
- hashchange를 듣기 때문에 메뉴 클릭, 뒤로 가기, 앞으로 가기가 모두 같은 함수로 처리된다. 새로고침하면 주소에 남은 #로 다시 표시한다.
- 완료 화면의 "내 예약 보기"와 내 예약의 "새로 예약하기"도 다른 영역으로 옮겨 가는 버튼이라, 주소를 `#myBookings` / `#prepare`로 같이 바꾼다.
  안 그러면 화면은 내 예약인데 메뉴는 예약하기에 머물렀다.

### 내 예약 필터 기준

| 필터 | data-filter | 보이는 예약 |
|---|---|---|
| 전체 | all | 확정한 예약 전부 |
| 예약됨 | booked | 상태가 "취소됨"이 아닌 예약 (아직 갈 곳) |
| 취소됨 | cancelled | 상태가 "취소됨"인 예약 |

- 목록 범위만 바꾸는 것이라 링크가 아니라 button이다. 누른 버튼 하나만 is-active, aria-pressed="true".
- 목록 위에 "전체 3건", "예약됨 2건 / 전체 3건"처럼 지금 보이는 개수를 쓴다.
- 결과가 없을 때 안내를 둘로 나눴다.
  예약이 아예 없으면 기존 "아직 확정한 예약이 없습니다. 예약 준비에서…", 고른 상태에만 없으면 "취소됨 상태인 예약이 없습니다. 확정한 예약은 모두 n건이고, 아래 전체 보기를 누르면 모두 볼 수 있습니다." + 전체 보기 버튼(11주차)
- 취소됨을 보고 있다가 새 예약을 확정하면 방금 넣은 예약이 안 보이므로 필터를 전체로 돌린다.

### 모바일 메뉴

- 기존 768px 미디어 쿼리 안에서 메뉴를 접고 "메뉴 열기" 버튼을 보인다. 769px 이상은 버튼이 숨고 메뉴가 가로로 펼쳐진다.
- 버튼을 누르면 nav에 is-open을 붙였다 뗀다. 메뉴 표시, 버튼 문구(메뉴 열기/메뉴 닫기), aria-expanded를 setMenuOpen 하나에서 같이 바꾼다.
- 메뉴에서 목적지를 누르면 그 영역으로 이동하고 메뉴는 닫힌다. 다시 열면 그 메뉴가 현재 위치로 표시돼 있다.
- 버튼은 aria-controls="siteNav"로 메뉴와 연결했다. 닫힌 메뉴는 display: none이라 Tab으로 들어가지 않는다.

### 확인 순서

1. 주소에 #가 없는 상태로 열기 → 서비스 소개만 강조
2. 메뉴를 차례로 누르기 → 주소 끝(#prepare, #myBookings…), 도착 영역, 강조된 메뉴가 같이 바뀜
3. 뒤로 가기 / 앞으로 가기 → 강조가 주소를 따라감. 새로고침해도 그대로
4. 예약 준비에서 이름 쓰고 규칙 확인 → 예약 두 건 확정 → 내 예약 보기(메뉴 강조가 내 예약으로) → 한 건 취소
5. 필터 전체 2건 / 예약됨 1건 / 취소됨 1건 확인
6. 예약됨에서 나머지 한 건 취소 → 카드가 빠지고 "예약됨 상태인 예약이 없습니다…" 안내 → 전체를 누르면 2건이 돌아옴
7. 새로고침 → 내 예약 목록과 상태 그대로
8. 폭을 768px 이하로 → 메뉴가 접히고 "메뉴 열기" 버튼. 열기·닫기를 반복하며 문구와 aria-expanded 확인 → 내 예약 선택 → 이동하면서 메뉴 닫힘

## 11주차: 웹 접근성 개선

10주차까지 만든 화면을 "알아볼 수 있는가 → 이해할 수 있는가 → 조작할 수 있는가" 순서로 점검했다.
마우스 없이 Tab·Enter·Esc만으로 예약하고, 내 예약을 거르고, 취소하는 데까지 가 보면서 막히는 곳을 고쳤다.

### 개선 전 → 개선 후

| 영역 | 개선 전 | 개선 후 |
|---|---|---|
| 글자 대비 | 푸터 글자 `#747786`이 배경 대비 4.17:1 (일반 글자 권장 4.5:1 미달) | 보조 글자색 `#5e6272`로 맞춰 5.68:1 |
| 초점 표시 | 초점 외곽선 `#a8ccbd`가 흰 배경 대비 1.74:1이라 Tab으로 어디 있는지 잘 안 보임 | 진한 초록 `#2f6b5a`(6.23:1). 어두운 화면에서는 `#8cc2ad`로 바꿔 배경에 안 묻히게 |
| 선택 상태 | 현재 메뉴·선택한 필터·선택한 탭을 배경색으로만 구분 | aria-current / aria-pressed / aria-selected를 CSS가 읽어 굵기 800 + 밑줄. 색을 못 구분해도 찾을 수 있다 |
| 오류 표시 | 붉은 글자·붉은 테두리 | 오류 문장 앞에 ⚠ 기호. 예약 흐름(이름·동네·날짜·시간)과 이메일 칸에 aria-invalid, 입력칸과 오류 문장을 aria-describedby로 연결 |
| 본문 바로가기 | 첫 Tab이 메뉴 버튼·메뉴 5개를 다 지나야 본문에 닿음 | 첫 Tab에 "본문 바로가기"가 왼쪽 위에 나타나고 Enter로 `<main id="content" tabindex="-1">`에 초점 |
| 탭 제목 | 어느 메뉴를 봐도 "동네공부방 \| 서비스 소개" 고정 | 메뉴를 옮길 때마다 "내 예약 \| 동네공부방"처럼 현재 메뉴 이름이 들어감 |
| 모바일 메뉴 | 열면 메뉴 닫기 버튼으로 돌아가서 눌러야만 닫힘 | Esc로 닫히고 버튼 문구·aria-expanded가 같이 돌아오며, 초점은 메뉴 버튼으로 |
| 카드 버튼 이름 | 예약이 여러 건이면 "자세히 보기"·"예약 취소"가 똑같이 여러 번 읽힘 | "망원동 1인석 2026-12-20 11:00 예약 취소"처럼 어떤 예약의 버튼인지 이름에 붙임(aria-label, 화면 글자는 그대로) |
| 글자 수 표시 | 예약자 이름·후기 글자 수에 aria-live가 있어 한 글자마다 숫자를 읽음 | aria-live를 빼고 입력칸의 aria-describedby로만 연결 |
| 취소 후 초점 | 항상 "새로 예약하기"로 이동해서 목록 위치를 잃음 | 전체 보기면 취소한 카드의 자세히 보기, 예약됨 필터라 카드가 빠지면 선택된 필터 버튼 |
| 빈 결과 | "다른 상태를 눌러 보세요" 문장만 있어서 위로 다시 올라가 필터를 찾아야 함 | 바로 아래 "전체 보기" 버튼. 누르면 전체 목록, 전체 버튼에 초점 |

- 서비스 이미지 alt("공부방 책상에 앉아 노트북으로 공부하는 사람")는 그림 장면과 맞아서 그대로 뒀다.
- 노션의 대화상자 × 버튼 이름 붙이기는 이 서비스에 dialog가 없어서 해당 없음. 대신 같은 글자가 반복되는 카드 버튼에 이름을 붙였다.
- 노션의 필터 결과 수 알림은 10주차에 넣은 `#myBookingsCount`(aria-live)가 이미 "예약됨 1건 / 전체 2건"으로 알려 줘서 그대로 썼다.
- 후기 폼의 조건부 영역 hidden + disabled, 오류 문장 + aria-invalid + 초점, 저장 중 aria-busy는 9주차 코드에 이미 있어서 다시 확인만 했다.
- 노션은 모바일을 600px로 나누지만 4주차부터 써 온 768px 하나를 그대로 쓴다.
- 본문 바로가기로 주소가 `#content`가 되면 본문 맨 위인 서비스 소개를 보는 것과 같으므로 메뉴 강조·탭 제목도 서비스 소개로 둔다.

### 확인 순서

1. 새로고침하고 마우스를 누르지 않은 채 Tab → 왼쪽 위 "본문 바로가기" → Enter → 다음 Tab이 주요 기능의 첫 탭
2. 메뉴를 차례로 이동 → 주소 #, 밑줄·굵기, 탭 제목이 같이 바뀜
3. 이름 없이 예약 시작 → ⚠ 오류 문장, 이름 칸 초점 → 동네·날짜·시간도 같은 방식
4. 예약 두 건 확정 → 전체에서 한 건 취소(초점이 그 카드에 남음) → 예약됨에서 나머지 취소(초점이 예약됨 버튼) → 전체 보기(초점이 전체 버튼)
5. 768px 이하에서 메뉴 열기 → Esc → 닫히고 메뉴 버튼에 초점 → Enter로 다시 열기
6. 어두운 화면에서 Tab으로 초점 외곽선 확인

## 12주차: 재사용 가능한 UI 컴포넌트

같은 역할의 요소가 화면 여러 곳에 반복되는데, 색·높이·초점선을 요소마다 따로 적어 두어서 하나를 고치면 나머지와 어긋났다.
JavaScript도 탭·카드 버튼마다 이벤트를 따로 붙이고 있었다. 이번 주에는 반복되는 모양은 CSS 변수·공통 클래스로, 반복되는 동작은 함수 하나로 모았다.

### 컴포넌트 3종

| 컴포넌트 | 위치 | 사용 목적 | 동작 방법 | 상태 표시 |
|---|---|---|---|---|
| 탭 (6주차 → 개선) | 주요 기능 | 빈자리 확인 / 시간 단위 예약 / 이용 후기 설명을 한 자리에서 바꿔 본다 | 클릭, 또는 탭에 초점을 두고 ← → (↑ ↓) 로 이웃 탭, Home·End로 처음·끝. 다음 Tab은 열린 패널로 | 선택된 탭: 초록 배경 + 굵기 + 밑줄, aria-selected="true". 선택 안 된 탭은 tabindex -1 |
| 아코디언 (신규) | 자주 묻는 질문 | 예약 전에 궁금한 것(취소 기한, 스터디룸 인원, 시간 겹침, 저장 위치)을 질문만 늘어놓고 필요한 답만 펼친다 | 질문 버튼 클릭 또는 Tab으로 이동해 Enter·Space. 여러 개를 같이 펼칠 수 있다 | 펼친 질문: 연한 초록 배경 + 굵기 800 + 기호 + → −, aria-expanded="true" |

내 예약의 "자세히 보기 ↔ 접기"도 아코디언과 같은 펼치기 함수를 쓰도록 바꿨다.

### 반복 UI 정리 (노션 과제: 버튼과 목록 항목)

선택한 반복 UI는 **버튼**과 **내 예약 카드**다.
사용자는 버튼으로 예약을 시작·진행·취소하고, 내 예약 카드에서 예약을 펼쳐 보고 취소한다.

| 구분 | 내용 |
|---|---|
| 함께 쓰는 것 (버튼) | `:root`의 색 토큰(`--green`, `--muted`, `--line`, `--danger`, `--focus` …), 최소 높이 `--control-height: 44px`(모바일 48px), 모서리 `--radius: 8px`, 글꼴, 초점선 3px. 주요·보조·탭·필터·아코디언 버튼이 같은 공통 규칙 하나를 쓴다 |
| 버튼마다 다른 것 | 주요(primary) = 초록 배경, 보조(secondary) = 흰 배경 + 초록 테두리, 위험(danger-button) = 주요 버튼 모양에 붉은 배경. 글자 |
| 함께 쓰는 것 (카드) | 카드 한 장의 구조는 `<template id="bookingItemTemplate">` 하나, 만드는 함수는 `makeBookingItem(booking)` 하나 |
| 카드마다 다른 것 | 공부방·자리, 날짜·시간, 예약자, 버튼 이름(aria-label에 예약 내용) |
| 행동으로 바뀌는 것 | 선택(탭·필터 밑줄+굵기), 초점(3px 외곽선), 펼침(자세히 보기 ↔ 접기), 취소(라벨 "취소됨", 점선 테두리, 시간 취소선, 버튼 "취소 완료" 비활성) |

### 재사용 구조

| 종류 | 이름 | 하는 일 |
|---|---|---|
| CSS 변수 | `:root`의 `--green` 등 | 색에 역할 이름을 붙임. 어두운 화면은 `body.dark { --focus: #8cc2ad; }`처럼 값만 바꿈 |
| CSS 공통 규칙 | `.primary-button, .secondary-button, .tab, .filter-button, .accordion-button` | 높이·모서리·글꼴·커서·초점선 |
| JS 함수 | `setupTabs(tablist)` / `selectTab(tablist, tab)` | role="tablist" 묶음마다 click·keydown을 한 번 붙임. 탭을 더 만들어도 같은 HTML 구조면 그대로 동작 |
| JS 함수 | `setExpanded(button, open)` / `toggleExpanded(button)` | aria-controls로 연결된 영역의 hidden과 aria-expanded, `data-open-text`·`data-closed-text` 글자를 같이 맞춤. 아코디언과 자세히 보기가 같이 씀 |
| JS 함수 | `openModal(dialog, opener)` / `closeModal(dialog)` | .modal 아무 데나. `data-modal-close` 버튼·바깥 클릭으로 닫고, close 이벤트에서 연 버튼으로 초점 복귀 |
| JS 함수 | `makeBookingItem(booking)`, `createReviewItem(review)` | 데이터 한 건 → 목록 한 줄. 목록 함수(renderMyBookings, renderReviews)는 빈 목록 안내와 순서만 맡음 |
| 이벤트 위임 | `myBookingList`의 click 하나 | 카드마다 붙이지 않고 버튼의 `data-action`(detail, cancel)과 카드의 `data-id`로 구분 |

- 메뉴의 현재 위치는 한 페이지 안의 위치라서 `aria-current="page"`를 `"location"`으로 바꿨다(노션 유닛 2-5).
- 후기 카드의 날짜는 `<time datetime>`으로, 불편했던 점이 있는 후기는 글("불편했던 점: 소음")과 왼쪽 붉은 선으로 구분한다.
- 노션 유닛 2의 901px 이상 왼쪽 고정 메뉴는 넣지 않았다. 이 페이지는 머리말에 서비스 이름·설명이 있고 메뉴가 5개라 가로 메뉴로 충분했고,
  10주차부터 768px 하나로 메뉴를 접어 왔다. 넓은 화면과 좁은 화면이 같은 링크(`#about` …)를 쓰는 구조는 그대로다.
- 11주차에는 dialog가 없어서 노션의 대화상자 항목을 건너뛰었는데, 이번 주 취소 확인 모달로 채웠다.
- 어두운 화면은 초점색만 변수로 바꿨다. 나머지 색은 9~11주차에 `body.dark .○○`로 하나씩 맞춰 둔 규칙이 많아서, 한꺼번에 변수로 바꾸면 입력칸 글자처럼 어두운 화면용 규칙이 없는 곳이 깨진다. 새 컴포넌트(아코디언·모달)도 같은 방식으로 어두운 화면 규칙을 붙였다.

### 확인 순서

1. 주요 기능 첫 탭에 Tab → → 키 두 번 → End → Home. 선택·초점·패널이 같이 옮겨 감. 다음 Tab은 열린 패널

## 9주차 추가 기능: 이용 후기 쓰기

주요 기능 탭에 "이용 후기"를 소개만 해 두고 실제로 남길 곳이 없었다.
그래서 다녀온 공부방의 후기를 쓰는 폼(#reviewForm)을 내 예약 아래에 만들었다. 메뉴에 "후기 쓰기"도 추가했다.

예약 흐름(7주차·중간고사)은 이미 단계마다 필수값 검사가 있어서 그대로 두고,
글을 직접 써야 하는 후기 폼에 이번 주 내용(글자 수, 조건부 입력, submit 상태 처리)을 적용했다.

### 입력 항목과 조건

| 항목 | 요소 | 조건 | 도움말 / 오류 문장 |
|---|---|---|---|
| 다녀온 동네 | select | 필수 | "후기는 동네별로 모아서 보여 줍니다." / "다녀온 동네를 선택해 주세요…" |
| 이용한 자리 | radio (1인석·스터디룸) | 기본 1인석 | |
| 후기 내용 | textarea | 필수, 앞뒤 공백 빼고 20자 이상, 최대 200자 | 쓰는 동안 "n / 200자", "n자 더 쓰면 등록할 수 있습니다" → 20자 넘으면 "등록 조건을 충족했습니다"(초록 테두리) / 빈 값 "후기 내용을 입력해 주세요", 부족 "지금 n자라서 m자 더 필요합니다" |
| 불편했던 점도 같이 남길게요 | checkbox | 체크하면 아래 영역이 열림 | |
| 가장 불편했던 점 | radio (소음·조명·콘센트·냉난방) | 영역이 열려 있을 때만 필수 | "가장 불편했던 점을 하나 골라 주세요. 남기지 않으려면 위 체크를 해제하면 됩니다." |

- label의 for와 입력의 id를 맞췄고, 도움말·글자 수·오류 문장은 aria-describedby로 입력에 연결했다.
- 불편한 점 영역은 체크 상태 하나로 hidden, 라디오 disabled, 체크박스의 aria-expanded를 같이 바꾼다(syncIssueFields).
  disabled라서 닫혀 있으면 Tab으로 들어가지 않고 FormData에도 안 들어간다. 닫으면 그 안의 오류도 지운다.
- 상태는 색과 문장을 같이 바꾼다. 오류는 붉은 테두리·배경 + 오류 문장 + aria-invalid, 충족은 초록 테두리 + "등록 조건을 충족했습니다".
- 쓰는 중에는 빨간 오류를 띄우지 않는다. 제출에서 한 번 오류가 난 칸만 값을 고칠 때마다 다시 검사해서 바로 해제한다.
- 오류 문장 자리(min-height)를 미리 잡아 둬서 오류가 생기고 사라져도 아래 내용이 밀리지 않는다.

### 제출 처리 (script.js handleReviewSubmit)

1. form의 submit 이벤트 하나로 처리한다. 버튼 클릭이든 Enter든 같은 검사를 거친다.
2. 세 항목을 모두 검사해서 틀린 칸을 한꺼번에 표시하고, "고칠 항목이 n개 있습니다" 안내 후 첫 오류 칸으로 포커스를 옮긴다. 제출은 안 된다.
   하나씩 고칠 때마다 남은 개수로 바뀌고, 다 고치면 안내가 사라진다.
3. 통과하면 버튼을 "등록하는 중…"으로 바꾸고 disabled, form에 aria-busy="true". 연속으로 눌러도 한 번만 저장된다.
4. 0.8초 뒤 localStorage(dongneReviews)에 저장한다(saveReview). 서버는 없다. 새로고침해도 최근 후기 목록이 남는다.
5. 성공하면 폼을 처음 상태로 비우고 "○○ 후기를 등록했습니다" 안내, 최근 후기 맨 위에 추가된다.
6. 실패하면 쓴 내용을 그대로 두고 버튼만 다시 살린 뒤 "등록하지 못했습니다. 쓴 내용은 그대로 두었으니…" 안내.

실패는 일부러 일으켜야 볼 수 있다. 주소 끝에 `?save-error=1`을 붙여 열면 saveReview가 저장 전에 오류를 던진다
(script.js의 forceSaveFailure, saveReview). localStorage가 막혀 저장이 안 될 때도 같은 실패 안내로 간다.

"처음부터 다시 쓰기"(resetReviewForm)는 입력값, 글자 수, 도움말 문장, 오류 표시, 불편한 점 영역(닫고 disabled), 버튼, 상태 문구를 모두 처음으로 돌린다.

### 확인 순서

1. 아무것도 안 쓰고 후기 등록하기 → 동네·후기 두 칸에 오류, "고칠 항목이 2개", 동네 칸에 포커스
2. 후기에 한 글자 → "1 / 200자", 오류 문장이 "지금 1자라서 19자 더 필요합니다"로 바뀜
3. 동네 선택 → 동네 오류 해제, 안내가 "고칠 항목이 1개"로 바뀜
4. 후기를 20자 넘게 → 오류 해제, 초록 테두리 + "등록 조건을 충족했습니다", 상단 안내 사라짐
5. 불편했던 점 체크 → 항목 영역이 열리고 선택 가능. 고르지 않고 등록 → 항목 오류
6. 체크 해제 → 영역이 닫히고 라디오 disabled, 항목 오류도 사라짐
7. 다시 체크하고 항목 골라 등록 → "등록하는 중…" 버튼 잠김 → 완료 안내, 최근 후기 맨 위에 추가, 폼 비워짐
8. `?save-error=1`로 열어 같은 순서로 등록 → 실패 안내, 입력값 그대로, 버튼 다시 누를 수 있음
9. 처음부터 다시 쓰기 → 전부 처음 상태

## 사용자 흐름

```
예약 준비: 이름 입력 + 이용 규칙 확인 → [예약 시작하기]
  1 / 3 공부방 선택   : 동네(필수), 자리 종류        → [날짜·시간 고르기]
  2 / 3 날짜·시간 선택 : 이용 날짜(필수), 시작 시간(필수), 이용 시간
                         [공부방 다시 고르기] ←       → [예약 내용 확인하기]
  3 / 3 내용 확인      : 예약자 / 공부방 / 날짜·시간
                         [날짜·시간 수정하기] ←       → [예약 확정하기]
                         (시간이 겹치면 여기서 멈추고 수정하기로 안내)
  예약 완료            : 확정 문장 + 취소 안내      → [다시 예약하기] → 1 / 3
                                                     → [내 예약 보기]
내 예약 (중간고사)     : 예약 목록 → [자세히 보기] / [예약 취소] → [새로 예약하기]
```

- 6주차에 만든 "예약 시작하기" 버튼(규칙을 확인해야 활성화)을 흐름의 입구로 썼다.
  규칙 확인 조건은 그대로 두고, 이름이 비어 있는지만 추가로 확인한다.
- 예약자 이름은 6주차 예약 준비 영역의 이름 칸을 그대로 쓴다. 흐름 안에서 한 번 더 묻지 않는다.
- 단계는 진행 표시(1 / 3 · 공부방 선택)로 지금 어디인지 보여 주고, 완료되면 "예약 완료"로 바뀐다.
- 단계가 바뀌면 새 단계의 첫 입력칸이나 버튼으로 포커스를 옮긴다.
  처음엔 이걸 안 해서 숨겨진 단계의 버튼에 포커스가 남아 있었다.

## 인터랙션 시나리오

| 행동 | 이벤트 · 조건 | 화면 반응 → 다음 상태 |
|---|---|---|
| 규칙 확인 후 이름 없이 예약 시작 | click · 이름이 비어 있음 | 이름 칸 아래에 "예약자 이름을 입력해 주세요" 안내, 이름 칸 붉게 표시하고 포커스 → 예약 영역은 열리지 않음 |
| 이름 쓰고 예약 시작 | click · 이름 있음 | 안내 지움, 공부방 예약 영역이 열림 → 1 / 3 공부방 선택 |
| 동네 없이 다음 | click · 동네 빈 값 | 동네 칸 붉게, "동네를 선택해 주세요" 안내 → 1단계에 머묾 |
| 자리 종류를 스터디룸으로 바꿈 | change · 스터디룸 | 같이 오는 사람도 규칙을 지켜야 한다는 안내 표시. 1인석으로 바꾸면 숨김 |
| 날짜나 시작 시간 없이 다음 | click · 날짜 또는 시간 빈 값 | 빠진 칸만 붉게, 날짜가 먼저 빠졌으면 날짜 안내 → 2단계에 머묾 |
| 확인 단계에서 날짜·시간 수정하기 | click · 수정 요청 | 입력값을 지우지 않고 2단계로 → 고친 뒤 다시 확인하면 새 값으로 다시 채움 |
| 예약 확정하기 | click | 진행 표시가 "예약 완료"(초록)로 바뀌고 확정 문장 표시 → 완료 |
| 다시 예약하기 | click · 초기화 | 동네·자리·날짜·시간·이용 시간, 오류 문구와 붉은 표시, 스터디룸 안내, 확인·완료 문장, 진행 표시를 처음으로 → 1 / 3 |

다시 예약하기에서 이름과 규칙 확인은 지우지 않는다. 둘은 예약 흐름이 아니라 그 앞의 예약 준비 영역 값이고,
같은 사람이 한 번 더 예약하는 경우라 다시 쓰게 할 이유가 없다고 봤다.

확인 화면 값은 "예약 내용 확인하기"를 누를 때마다 지금 입력칸 값으로 다시 채운다.
그래서 이전 단계에서 고친 값이 따로 처리하지 않아도 확인 화면에 반영된다.

## 주차별 작업 기록

### 2주차 - HTML 구조

1주차엔 h1이랑 p 두 줄이 전부였는데, 이번에 header / main / footer로 나눴다.
main 안에는 서비스 소개, 주요 기능, 이용 방법, 소식 받기를 각각 section으로 묶고 id를 달았다.

이렇게 한 이유는:

- 처음 온 사람이 "뭐 하는 서비스지 → 뭘 할 수 있지 → 어떻게 쓰지" 순서로 읽게 하고 싶었다.
  이 순서를 body 첫 줄 주석에 먼저 적어두고 그대로 section 순서로 옮겼다.
- 주요 기능은 순서를 바꿔도 상관없어서 ul, 이용 방법은 순서를 지켜야 해서 ol로 했다.
- nav의 href랑 section의 id를 맞춰서 원하는 영역으로 바로 넘어가게 했다.
- alt는 파일명 말고 그 자리에서 이미지가 무슨 얘기를 하는지 적었다.
- label의 for랑 input의 id를 email로 맞춰서 라벨을 눌러도 입력칸이 잡히게 했다.

### 2주차 - 구조 비교 메모

같은 화면을 시맨틱 태그 없이 div로만 짜면 이렇게 된다.

```html
<div class="top">
  <div class="title">동네공부방</div>
  <div class="menu"><a href="#about">서비스 소개</a></div>
</div>
```

브라우저에 보이는 결과는 거의 같은데, 차이는 세 군데였다.

**정보 계층** - div는 전부 같은 무게라서 코드만 봐서는 뭐가 제목이고 뭐가 본문인지 알 수 없다.
h1 → h2 → h3을 쓰면 읽는 순서가 코드에 그대로 남는다. 목록도 ul이냐 ol이냐에 따라
"순서가 있는 과정"인지 "순서 상관없는 항목"인지까지 표시된다.

**시맨틱 구조** - header, nav, main, section, footer는 태그 이름 자체가 그 덩어리의 역할이다.
div.top, div.menu 같은 건 클래스 이름을 지은 사람만 안다. 나중에 코드를 다시 볼 때도 차이가 크다.

**접근성** - 스크린리더는 시맨틱 태그를 기준으로 영역을 건너뛴다. div만 있으면 그게 안 돼서
처음부터 끝까지 순서대로 들어야 한다. label-input 연결이나 alt도 같은 이야기다.
없으면 이 입력칸이 뭘 넣는 칸인지, 이미지가 무슨 그림인지 알 방법이 없다.

### 3주차 - CSS

.feature-list에 display: flex랑 gap: 20px을 주고, .feature-card에 flex: 1과 배경색, 테두리를 넣었다.

세로로 길게 늘어지던 기능 3개가 같은 너비 카드로 한 줄에 들어갔고 간격도 일정해졌다.
세 기능이 같은 종류의 정보라는 게 한눈에 보여서 비교하면서 읽기 편해졌다.

### 4주차 - 반응형

#### 확인한 문제

개발자 도구를 390px로 놓고 3주차 화면을 열어봤다.

- 메뉴 4개가 한 줄에 그대로 남아서 글자가 서로 붙었다.
- 소개 글과 이미지가 가로로 붙어 있어 글이 한 줄에 서너 글자씩만 들어갔다.
- 기능 카드 3개가 flex: 1로 균등 분할되면서 카드 하나 폭이 100px도 안 됐다.
- 이메일 입력창과 버튼이 서로 밀어내서 버튼 글자가 두 줄로 깨졌다.

#### 수정한 내용

viewport 메타 태그는 1주차에 이미 넣어둬서 그대로 뒀다.

- header / main / footer에 width: 100%를 추가했다. max-width: 1100px만 있으면
  넓은 화면은 잡히지만 좁은 화면에서 안쪽 여백까지 계산이 안 맞았다.
- .service-image를 width: 360px에서 width: 100% + max-width: 360px + height: auto로 바꿨다.
  화면이 좁아지면 이미지가 따라 줄고, 넓어져도 360px을 넘지 않는다.
- .site-nav와 .about-layout에 flex-wrap: wrap을 줘서 자리가 부족하면 다음 줄로 넘어가게 했다.
- .feature-list를 flex에서 grid로 바꿨다.
  grid-template-columns: repeat(auto-fit, minmax(260px, 1fr))이라서
  들어갈 수 있는 만큼만 열을 만들고 카드는 최소 260px을 지킨다.
  flex: 1일 때처럼 무조건 3등분되지 않는다. .feature-card의 flex: 1은 지우고 min-width: 0을 넣었다.
- 파일 맨 아래에 @media (max-width: 768px) 블록을 하나 추가해서
  메뉴 / 소개 / 기능 카드 / 폼을 전부 한 열로 바꾸고 글자 크기와 여백을 줄였다.

#### 달라진 점

1100px / 769px / 768px / 390px에서 확인했다.

| 너비 | 결과 |
|---|---|
| 1100px | 카드 3열, 소개 글과 이미지 가로 배치 |
| 769px | 카드 2열. 미디어 쿼리는 아직 안 걸린다 |
| 768px | 메뉴·카드·폼이 한 열로 바뀐다 |
| 390px | 가로 스크롤 없음, 버튼이 화면 폭에 꽉 참 |

한 군데 걸린 게 있다. 768px 이하에서 .about-layout이 세로 배치가 되니까
이미지에 준 flex: 0 1 360px의 360px이 너비가 아니라 높이 기준으로 잡혀서
이미지가 세로로 늘어났다. 미디어 쿼리 안에서 flex: 0 1 auto로 되돌려서 해결했다.
flex-basis가 방향에 따라 다른 축을 가리킨다는 걸 이번에 알았다.

### 5주차 - JavaScript로 신청 결과 알려주기

#### 추가한 기능

소식 받기 영역의 빈자리 알림 신청 폼에 JavaScript를 붙였다.
4주차까지는 버튼을 눌러도 페이지가 새로고침될 뿐 신청이 됐는지 알 방법이 없었다.

- body 닫는 태그 바로 위에서 script.js를 불러오고, Console에 연결 문장이 찍히는지 먼저 확인했다.
- 폼, 이메일 입력칸, 안내 문구(#subscribeMessage), 버튼(#subscribeButton)을 querySelector로 선택했다.
- 폼의 submit 이벤트에 subscribe 함수를 연결했다.
  버튼 click 대신 submit을 쓴 건 입력칸에서 엔터를 쳐도 똑같이 동작하게 하려고.
  submit은 기본으로 페이지를 새로고침해서 event.preventDefault()로 막았다.

#### 조건 처리

| 입력 | 안내 문구 | 스타일 / 버튼 |
|---|---|---|
| 비어 있음 | 이메일을 입력해 주세요. | 붉은 배경(is-error), 입력칸에 다시 포커스 |
| 이메일 입력 | ○○ 으로 빈자리 알림을 보내 드릴게요. | 초록 배경(is-done), 버튼 "신청 완료" + disabled |

문구는 makeSubscribeMessage 함수가 입력값을 받아 if로 골라서 돌려준다.
신청 여부는 let isSubscribed에 담았다. false로 시작해서 신청하면 true가 된다.
신청이 끝나면 버튼과 입력칸을 disabled로 막아서 같은 신청이 반복되지 않게 했다.

@가 빠진 값은 input type="email"이 제출 자체를 막아서 브라우저 기본 안내가 뜬다.
그래서 JavaScript 쪽 조건은 빈 값인지 아닌지만 나눴다.

#### 확인

- 빈 값 제출 → 경고 문구, 버튼 그대로
- 이메일 입력 후 제출 → 완료 문구, 버튼 비활성화, 새로고침 없음
- 390px 폭에서 버튼과 문구가 잘리지 않고 가로 스크롤 없음
- Console 오류 없음

### 6주차 - 이벤트와 탭

#### 추가한 기능

이용 방법 다음에 "예약 준비" 섹션(#prepare)을 새로 만들고 메뉴에도 링크를 달았다.
기존 주요 기능 카드 3개는 탭으로 바꿨다.

| 이벤트 | 요소 | 화면 변화 |
|---|---|---|
| click | 화면 밝기 버튼(#themeButton) | body에 dark 클래스를 붙였다 뗐다 하면서 배경·카드 색이 바뀌고, 버튼 문구가 "어두운 화면으로 보기" ↔ "밝은 화면으로 보기"로 바뀐다 |
| input | 예약자 이름(#userName) | 쓰거나 지울 때마다 "0 / 10" 글자 수가 바뀐다. 10자를 채우면 is-full 클래스로 숫자가 붉게 굵어진다 |
| change | 이용 규칙 체크박스(#agreeCheck) | 안내 문구가 바뀌고, is-ready 클래스로 초록 배경이 되고, 예약 시작하기 버튼의 disabled가 풀린다. 체크를 해제하면 셋 다 원래대로 |
| click | 주요 기능 탭 3개(.tab) | 누른 탭만 초록색으로 채워지고, data-target으로 연결된 패널 하나만 보인다 |

change 쪽은 checked 값 하나(agreed)로 문구, 클래스, 버튼 상태를 같이 바꿨다.
기준이 하나라서 체크를 켜고 끌 때 셋이 항상 같은 상태로 움직인다.

예약 시작하기 버튼은 지금은 활성/비활성만 바뀌고 누른 뒤 동작은 없다.
예약 흐름은 다음 주차에 붙일 생각이다.

#### 탭으로 바꾼 이유

빈자리 확인 / 시간 단위 예약 / 이용 후기는 원래 카드 세 장이 나란히 있었는데,
한 줄 설명만 있어서 기능마다 설명을 더 쓰기엔 카드가 좁았다.
탭으로 바꾸면서 기능마다 설명을 한 문단씩 더 넣었고, 한 번에 하나만 보이니 화면도 덜 길어졌다.

- 탭은 querySelectorAll로 전부 잡고 forEach로 click을 연결했다.
- 누르면 resetTabsAndPanels로 전부 끄고 activateTab으로 누른 것만 켠다.
  is-active 클래스, aria-selected, 패널의 hidden을 같이 바꾼다.
- 탭 버튼의 data-target="#panel-booking"과 패널 id="panel-booking"을 맞춰서 연결했다.
- 기능 카드에 쓰던 .feature-list / .feature-card CSS는 안 쓰게 돼서 지웠다.

#### 테스트 결과

1100px / 768px / 390px 폭에서 확인했다.

| 확인 항목 | 결과 |
|---|---|
| 탭 세 개를 차례로 누르기 | 선택된 탭과 보이는 패널이 항상 하나씩 |
| 화면 밝기 버튼 두 번 누르기 | 어두운 화면 → 밝은 화면, 버튼 문구도 따라 바뀜 |
| 이름 입력 / 지우기 | 2 / 10 → 10 / 10(붉게) → 0 / 10 |
| 체크 → 해제 | 버튼 활성 → 비활성, 문구·배경도 같이 돌아옴 |
| 1100px | 탭 가로 한 줄, 버튼은 글자 폭만큼 |
| 768px | 탭이 세로로 쌓이고 버튼이 카드 폭에 꽉 참 |
| 390px | 가로 스크롤 없음, 탭·입력창·버튼 잘림 없음 |
| 키보드 | Tab으로 탭 사이 이동, Enter/Space로 탭 전환, Space로 체크박스 선택 |
| Console | 연결 확인 문장 외 오류 없음 |

어두운 화면을 만들 때 body.dark p로 문단 글자를 밝게 바꿨는데,
안내 문구(#agreeMessage)는 배경이 밝은 상자라 그대로 두면 밝은 글자가 밝은 배경 위에 올라간다.
그래서 #agreeMessage에는 글자색을 직접 지정해서 id 선택자가 body.dark p보다 우선하게 했다.

### 9주차 - 폼 UI와 입력 경험

위의 "9주차 추가 기능: 이용 후기 쓰기"와 "9주차 이용 후기 폼 테스트"가 9주차 작업이다.

- 주요 기능 탭의 "이용 후기"를 실제로 쓸 수 있는 폼으로 만들었다. 예약 흐름은 손대지 않았다.
- 5주차 소식 받기 폼은 빈 값만 확인하고 버튼을 잠갔다. 이번 폼은 항목별 오류, 입력 중 상태, 저장 중·실패까지 나눴다.
- 처음엔 고칠 항목 안내가 제출 때 숫자로 고정돼서, 하나를 고쳐도 "2개"가 남았다. 고칠 때마다 남은 개수로 다시 쓰게 바꿨다.
  저장 실패 문구는 이 갱신에 지워지지 않도록 "고칠 항목" 안내일 때만 바꾼다.

### 10주차 - 내비게이션과 정보 탐색

위의 "10주차 추가 기능: 메뉴와 내 예약 필터"와 "10주차 메뉴·필터 테스트"가 10주차 작업이다.

- 메뉴를 a 나열에서 nav > ul > li로 바꾸고, 7개를 목적지가 분명한 5개로 줄였다.
- 주소의 #와 메뉴 강조(is-current, aria-current)를 맞췄다. 뒤로 가기·새로고침도 hashchange와 첫 실행으로 처리된다.
- 내 예약에 전체·예약됨·취소됨 필터와 개수, 빈 결과 안내 두 종류를 넣었다.
  필터를 새로고침 뒤에도 써 볼 수 있게 내 예약도 localStorage에 저장한다.
- 768px 이하는 메뉴를 접고 버튼으로 연다. 노션 예제는 600px이지만 이 프로젝트는 4주차부터 768px 하나로 모바일을 나눠 와서 그대로 썼다.
- README 맨 위에 9주차 테스트 표가 잘못 올라가 있어서 테스트 결과 아래로 옮겼다.

### 11주차 - 웹 접근성

위의 "11주차: 웹 접근성 개선"과 "11주차 접근성 테스트"가 11주차 작업이다.

- 색 대비를 계산해 보니 푸터 글자와 초점 외곽선이 기준보다 낮아서 진하게 바꿨다.
- 선택 상태를 색 말고 굵기·밑줄로도 보이게 했다. 상태값(aria-current 등)을 CSS 선택자로 써서 화면과 코드가 같은 걸 가리킨다.
- 본문 바로가기, 탭 제목 갱신, Esc로 메뉴 닫기, 취소 후 초점, 빈 결과에서 전체 보기를 넣었다.
- 노션 예제의 dialog 항목은 이 서비스에 없어서 반복되는 카드 버튼 이름으로 대신했다.

### 12주차 - 재사용 가능한 UI 컴포넌트

위의 "12주차: 재사용 가능한 UI 컴포넌트"와 "12주차 컴포넌트 테스트"가 12주차 작업이다.

- 색을 `:root` 변수로 묶고, 버튼·탭·필터의 높이·모서리·초점선을 공통 규칙 하나로 모았다. 필터 버튼이 42px로 혼자 낮았던 것도 44px로 맞췄다.
- 주요 기능 탭을 `setupTabs(tablist)`로 바꾸고 방향키·Home·End를 넣었다.
- 자주 묻는 질문 아코디언과 예약 취소 확인 모달을 새로 만들었다. 펼치기 함수는 내 예약 자세히 보기와 같이 쓴다.
- 내 예약 카드 버튼은 카드마다 이벤트를 붙이지 않고 `data-action`으로 목록 하나에서 받는다. 후기 목록은 한 건 → 한 줄 함수로 나눴다.
